It is the modernized successor to AI-102, re-centered on agentic development and Microsoft Foundry — the unified platform for model management, agent configuration, and evaluation pipelines. You build, manage, and deploy generative AI apps and agents using Python. You need 700/1000 to pass and have 120 minutes. Python proficiency and familiarity with generative AI are assumed.

Key Azure / Foundry Services to Know

Service Quick Reference ▼

The exam centers on building on Microsoft Foundry and its connected services:

Microsoft Foundry Foundry Agent Service Foundry SDK / Azure AI Projects SDK Foundry Tools Azure OpenAI Azure AI Search Azure AI Content Understanding Azure AI Document Intelligence Azure AI Vision Azure AI Video Indexer Azure AI Language Azure AI Speech Azure AI Translator Content Safety / Prompt Shields Azure AI Evaluation SDK Managed Identity / Entra ID
Audience profile & how to use this guide ▼

You are an Azure AI engineer who builds, manages, and deploys agents and AI solutions that take advantage of Microsoft Foundry. You should have experience developing apps with Python and be familiar with general AI, generative AI, and Azure services. You collaborate with business stakeholders, solution architects, data scientists, DevOps engineers, and cloud security engineers.

  • Work through each domain tab — expand the concept blocks and master every key term and SDK / pattern.
  • Spend the most time on GenAI & Agents (30–35%) and Plan & Manage (25–30%) — together they are well over half the exam.
  • Then take all 3 timed practice exams (45 questions, 120 minutes each) under 🧪 Practice Exams.
  • Review explanations after each set, then retake to push past 70%.
What changed from AI-102 → AI-103 ▼
  • Agents are now the core. A dedicated, heavily-weighted domain covers building single and multi-agent solutions, tool/function calling, conversation memory, and approval/oversight flows.
  • Microsoft Foundry is the platform. Model catalog/deployment, agent configuration, evaluation, and observability all happen through Foundry projects and SDKs.
  • Multimodal generation (text-to-image and text-to-video, image/video editing) joins visual understanding in the computer vision domain.
  • LLM-first text analysis replaces a lot of the old "call the Language service" approach — extraction, sentiment, and translation via generative prompting and Foundry Tools.
  • Information extraction is its own domain: RAG ingestion, hybrid/vector search grounding, and Content Understanding + Document Intelligence pipelines.
🧭

Plan and manage an Azure AI solution

25–30% of exam
Choosing Foundry services & models ⭐ ▼
Model typesLLMs (large, broad reasoning), SLMs (small language models — cheaper, lower latency, edge/cost-sensitive), multimodal models (text + image/audio/video), and code models. Choose the smallest model that meets quality/latency/cost needs.
Foundry model catalogBrowse and deploy models from Azure OpenAI and partners. Pick by task, context window, modality, throughput, region, and cost.
Foundry ToolsBuilt-in capabilities (e.g., Content Understanding, Translator, search/grounding connectors) you attach to apps and agents rather than building from scratch.
Retrieval & indexing choiceFor grounding, choose an index/retrieval method: Azure AI Search (semantic, vector, hybrid) is the default for RAG; vector stores for embeddings; keyword/semantic where appropriate.
Agent integration servicesPick the right memory (conversation/thread state), tools (functions, APIs, search), and knowledge (indexes, files, Content Understanding) for an agent solution.
Set up AI solutions in Foundry ▼
Foundry projectThe container for your AI work — connected resources (models, search, storage), deployments, agents, and evaluation. Apps connect to a project via its endpoint and a credential.
Model & agent deploymentsDeploy a model to get an inference endpoint; configure capacity/quota (e.g., tokens-per-minute). Configure agents with instructions, tools, and a model deployment.
Deployment optionsStandard vs provisioned throughput, regional choices, and serverless vs hosted endpoints — chosen for latency, scale, and cost predictability.
CI/CD integrationIntegrate Foundry projects with CI/CD pipelines — version prompts/flows/agents, run evaluations as gates, and promote across dev/test/prod with infrastructure-as-code.
Manage, monitor & secure AI systems ▼
Quotas, rate limits & costManage TPM/RPM quotas, scaling, and rate limits per deployment. Control cost by right-sizing models, caching, and capping token usage; monitor spend by deployment.
Monitor model qualityTrack performance, drift, safety events, and grounding quality (is the model staying faithful to retrieved context?).
Monitor retrievalWatch data ingestion quality, search index health, and relevance/recall of the retrieval layer feeding RAG.
Security best practicesUse managed identity and keyless (Entra ID) credentials instead of API keys; restrict with private networking (private endpoints) and least-privilege RBAC role policies.
Responsible AI across generative & agentic systems ⭐ ▼
Safety filters & guardrailsConfigure Azure AI Content Safety filters (hate, sexual, violence, self-harm) with severity thresholds, plus jailbreak/risk detection and content moderation on inputs and outputs.
Responsible AI instrumentationApply evaluators and safety evaluations (groundedness, relevance, coherence, harmful-content) and explanation tooling to measure quality and risk before/after deployment.
AuditingImplement trace logging, provenance metadata (which sources grounded an answer), and approval workflows for sensitive actions.
Govern agent behaviorConstrain agents with oversight modes (human-in-the-loop / human-on-the-loop), explicit constraints, and tool-access controls so an agent can only call the tools/APIs it is permitted to.
🤖

Implement generative AI and agentic solutions

30–35% of exam ⭐ Largest Domain
Build generative applications with Foundry ⭐ ▼
Deploy & consume modelsDeploy LLMs, SLMs, code, and multimodal models, then call them with the Foundry / Azure AI Inference SDK (chat completions, structured outputs, streaming).
Retrieval-Augmented Generation (RAG)Ground responses by retrieving relevant chunks (usually from Azure AI Search) and injecting them into the prompt. Improves accuracy and reduces fabrication; cite sources for provenance.
Tool-augmented & multistep flowsDesign workflows that call tools/functions and chain multiple reasoning steps (plan → retrieve → act → respond).
Evaluate models & appsDetect fabrications (groundedness), and measure relevance, quality (coherence/fluency), and safety using the Azure AI Evaluation SDK / Foundry evaluations.
Connect an app to a Foundry projectUse the project endpoint + a credential (DefaultAzureCredential / managed identity) to get clients for models, agents, search, and evaluation.
Build agents with Foundry ⭐ ▼
Agent definitionAn agent has a role/goal, instructions, a model, a conversation-tracking approach (threads / runs / messages), and a set of tools defined by schemas.
Threads, runs & messagesIn the Foundry Agent Service, a thread holds the conversation (memory), messages are turns, and a run executes the agent against the thread (and may invoke tools).
Function calling & tool schemasDefine tools with a JSON schema; the model decides when to call them and returns structured arguments. Your code executes the function and returns results to the agent.
Agent toolsIntegrate APIs, knowledge stores, Azure AI Search, Content Understanding, code interpreter, file search, and custom functions.
Multi-agent orchestrationCompose specialized agents (e.g., planner + workers, or a connected/handoff pattern) so they collaborate on a task.
Autonomy & approval flowsBuild autonomous or semi-autonomous workflows with safeguards and approval (human-in-the-loop) controls before high-impact actions.
Agent monitoring & error analysisTrace agent runs, evaluate behavior (task success, tool-call correctness), and perform error analysis on failed runs.
Optimize & operationalize generative systems ▼
Tune generation behaviorPrompt engineering (clear instructions, few-shot examples, system messages) and model parameters — temperature/top_p (randomness), max_tokens, stop sequences.
Reflection & self-critiqueImplement chain-of-thought reasoning, model reflection, and self-critique loops where the model reviews and revises its own output to improve quality.
ObservabilitySet up tracing, token analytics, safety signals, and latency breakdowns (often via OpenTelemetry → Application Insights / Foundry tracing) for deployed apps and agents.
Orchestrate multiple models/flowsCombine multiple models, flows, or a hybrid of LLMs and rules engines — e.g., route easy requests to an SLM and hard ones to an LLM.

Implement computer vision solutions

10–15% of exam
Image & video generation ▼
Text-to-imageGenerate images from text prompts (and reference media) using image-generation models in Foundry (e.g., DALL·E / GPT-image-class models). Control size, quality, and count.
Text-to-videoGenerate video from text prompts and reference media using video-generation models; configure duration, resolution, and reference conditioning.
Image editingUse inpainting and mask-based edits to change only selected regions, plus prompt-driven modifications of an existing image.
Video editing workflowsEdit generated videos (trim, modify segments) and apply the platform's generation/editing controls.
Multimodal understanding ⭐ ▼
Visual context analysisPass images to a multimodal model to reason over visual content alongside text.
Captioning & visual Q&AProduce concise or detailed captions for single/multiple images, and answer questions grounded in visual evidence.
AccessibilityGenerate alt-text and extended image descriptions aligned to accessibility guidelines.
Azure AI Content UnderstandingIn Foundry Tools, extract structured visual characteristics from images and process/interpret video segments. Supports single-task and pro-mode pipelines.
Object/region detectionIdentify objects, components, or regions within images or video for downstream reasoning.
Responsible AI for multimodal content ▼
Visual content filtersClassify and block unsafe or disallowed visual content using Content Safety image moderation.
Indirect prompt injectionDetect and mitigate prompt-injection attacks embedded as text inside images (e.g., a malicious instruction printed on a photo) — use Prompt Shields / indirect-attack detection.
Visual policy enforcementApply watermarks, flag prohibited symbols, uphold brand-usage rules, and detect potentially inappropriate content.

Implement text analysis solutions

10–15% of exam
Language-model text analysis ⭐ ▼
LLM-first extractionUse generative prompting (and Foundry Tools) to extract entities, topics, summaries, and structured JSON outputs — often with structured-output / JSON schema to guarantee shape.
Sentiment, tone & safetyDetect sentiment, tone, safety issues, and sensitive content (PII) via prompting or Azure AI Language + Content Safety.
TranslationTranslate text with Azure Translator (in Foundry Tools) or LLM-powered translation flows; pick Translator for high-volume/deterministic, LLM for context-aware nuance.
Domain customizationCustomize model outputs for domain tasks — e.g., compliance summarization, domain-specific extraction — using tailored prompts/examples.
Speech solutions ▼
Speech-to-text & text-to-speechUse Azure AI Speech to transcribe audio (STT) and synthesize voice responses (TTS) for voice-enabled agentic interactions.
Speech as an agent modalityIntegrate speech as an input/output modality for agents, including custom speech models for domain vocabulary/accents.
Audio reasoningEnable multimodal reasoning directly from audio inputs (audio-capable models).
Speech translationTranslate speech into other languages using language models and Foundry Tools.

Implement information extraction solutions

10–15% of exam
Retrieval & grounding pipelines ⭐ ▼
Ingest & index contentIngest documents, images, audio, and video into an index (commonly Azure AI Search). Chunk content, generate embeddings, and store with metadata.
Search modes for groundingKeyword, semantic (re-ranking), vector (embedding similarity), and hybrid (vector + keyword) search. Hybrid + semantic ranking usually gives the best RAG relevance.
Enrichment & skillsetsApply built-in or custom skills (skillsets) during indexing to enrich text, images, and layout — e.g., OCR, entity extraction, embedding generation.
RAG ingestion with OCRFor scanned/PDF content, run OCR in the ingestion flow so text is searchable and groundable.
Connect retrieval to agentsWire the retrieval pipeline directly into workflows and agent tools (e.g., a search/knowledge tool) so agents can ground their answers.
Extract content from documents ▼
Multimodal document pipelinesCombine OCR, layout analysis, and field extraction to pull structured data from documents (forms, invoices, contracts).
Azure AI Document IntelligencePrebuilt and custom models extract text, key-value pairs, tables, and fields. Use it for structured document extraction feeding RAG/agents.
Content Understanding for groundingProduce clean, grounded representations of documents (and other modalities) for use with agents and RAG.
Analyzers → structured / MarkdownConfigure Content Understanding analyzers to emit structured or Markdown output for downstream reasoning by models and agents.

Exam Strategy & Tips

🤖 Agents & GenAI Is the Heaviest Domain (30–35%)

Know the Foundry Agent Service model cold: threads (conversation memory), messages, runs, tools (function calling, file search, code interpreter, Azure AI Search), and multi-agent orchestration. Understand when to add human-in-the-loop approval before high-impact tool calls.

🧭 Plan & Manage Is Second-Heaviest (25–30%)

Expect "choose the right model/service" and "secure/monitor this" scenarios. Default answers: smallest model that meets the need, managed identity / keyless over API keys, private endpoints, RBAC least privilege, and quotas/TPM for cost control.

📚 RAG & Grounding Show Up Everywhere

RAG reduces fabrication by grounding answers in retrieved context. Azure AI Search is the default retrieval store — know vector, semantic, and hybrid search, and that hybrid + semantic ranking usually wins. Always cite sources (provenance).

🛡️ Responsible AI Is Tested in Every Domain

Content Safety filters (severity thresholds), Prompt Shields for jailbreak and indirect prompt injection (including text hidden in images), evaluators for groundedness/relevance/safety, and tool-access controls + approval flows to govern agents.

📊 Evaluate Before You Trust

Use the Azure AI Evaluation SDK / Foundry evaluations to score groundedness (fabrication detection), relevance, coherence/fluency, and safety. Run evaluations as CI/CD gates before promoting a prompt, flow, or agent.

👁️ Vision = Generate AND Understand

Half the vision domain is generation (text-to-image/video, inpainting/mask edits) and half is understanding (captions, visual Q&A, alt-text, Content Understanding single-task vs pro-mode, object/region detection). Don't forget multimodal responsible-AI.

📑 Information Extraction ≠ Text Analysis

Info extraction is about grounding pipelines (ingest → enrich/OCR → index → retrieve) and document extraction (Document Intelligence + Content Understanding analyzers → structured/Markdown). Text analysis is LLM-first entity/sentiment/summary/translation. Read the scenario for which one it wants.

🐍 It's a Python, Foundry-First Exam

Code-flavored answers assume Python and the Foundry / Azure AI Projects SDK (connect to a project, get model/agent/search clients with DefaultAzureCredential). Prefer SDK + managed identity over raw REST + keys.

🧪 Format, Beta & Logistics

Pass score 700/1000, ~120 minutes, English (beta). As a beta exam, scores arrive after the beta period closes. Most questions cover GA features; commonly-used Preview features may appear. There is no penalty for guessing — answer everything.
